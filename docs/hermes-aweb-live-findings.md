# Hermes on aweb: source and live findings

Investigation: aweb-acft.1; approved plugin build: aweb-acft.3, 2026-10-18 (runs through 2026-10-19 UTC). This supersedes the contract and packaging assumptions in [the prototype memo](hermes-aweb-gateway-integration.md).

## Decision in brief

The intended arrangement is supported by Hermes's architecture: one Hermes gateway can own both its Telegram adapter and an aweb identity. Humans can stay on Telegram while the agent receives aweb mail/chat. It does **not** automatically connect a Telegram conversation to a later aweb reply: Hermes gives the two platforms different sessions. A Telegram-to-aweb request/answer workflow still needs explicit correlation and delivery back to the original Telegram target.

The unchanged plugin failed against pinned Hermes at startup and then dropped real chat because the plugin and server's event contracts disagree. The first history fallback fixed ordinary transport but introduced a control/clarification deadlock. Juan approved correcting that design in aweb-acft.3. The current plugin separates responsive control admission from ordered ordinary turns, binds replies/read receipts to each input, retains failed mail fetches for retry, and reports receive-path health from real stream evidence. The deterministic empty-history/hint regression now fails against the investigation baseline and passes against this build. See [build acceptance evidence](evidence/hermes-plugin-build-2026-10-18.md).

**Real model replies and Telegram remain untested:** the approved model credential is pending from Juan; no bot token has been provided. The blocked-turn evidence uses actual Hermes plugin commands and its real approval/clarify primitives without inference. The build is pending non-author exact-SHA review; it has not merged.

## Telegram groups and several Hermes bots

Telegram privacy mode normally restricts group input to relevant commands/replies; admin bots receive broader input. Disabling privacy requires re-adding the bot. Hermes then applies its own group gates: `TELEGRAM_REQUIRE_MENTION` defaults false; exclusive mentions of another bot are excluded by default. These are separate from Telegram's delivery policy. [Telegram privacy documentation](https://core.telegram.org/bots/features#privacy-mode), [Hermes adapter.py:5756](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/plugins/platforms/telegram/adapter.py#L5756), [6379](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/plugins/platforms/telegram/adapter.py#L6379).

“Bots never see bots” is no longer an accurate universal statement. Current Telegram documentation permits command-directed or reply-directed group bot traffic when at least one participant enables Bot-to-Bot Communication Mode. An enabled receiver with admin rights or privacy disabled can also receive general bot chatter. Private bot-to-bot messages require both bots to enable the mode. This was verified in current documentation, not with a bot token. [Telegram bot-to-bot contract](https://core.telegram.org/api/bots/bot-to-bot).

Hermes carries `is_bot` from Telegram input. Its default bot-admission mode is `none`; `TELEGRAM_ALLOW_BOTS=mentions|all` enables the bot bypass of human allowlists (other explicit chat/user grants are also relevant). `TELEGRAM_BOTS_REQUIRE_MENTION=true` suppresses another bot's plain chatter and quote-only replies; that extra gate defaults false and free-response/guest branches can bypass it. Own-message echoes are dropped. A separate default loop budget admits at most 20 bot inputs in 300 seconds, then cools the conversation for 600 seconds. These controls reduce loops; they do not create a shared agent conversation or prove an arbitrary workflow terminates. [Telegram adapter.py:875](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/plugins/platforms/telegram/adapter.py#L875), [5774](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/plugins/platforms/telegram/adapter.py#L5774), [6136](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/plugins/platforms/telegram/adapter.py#L6136), [6358](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/plugins/platforms/telegram/adapter.py#L6358), [authz_mixin.py:564](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/authz_mixin.py#L564), [617](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/authz_mixin.py#L617), [bot_loop_guard.py:22](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/bot_loop_guard.py#L22).

## Root causes, fixes and remaining limits

1. **Hermes lifecycle mismatch — fixed.** Hermes [run_adapters.py:204](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/run_adapters.py#L204) always supplies `is_reconnect`, including cold boot. Baseline plugin `adapter.py:121` accepted no keyword. The fix adopts the current keyword-only signature. A test calling the actual Hermes lifecycle failed first for both initial and reconnect calls, then passed; it also registers through actual `PluginContext`.

2. **Plugin/server chat event disagreement — bounded plugin fallback.** [Server summaries](../server/src/aweb/routes/events.py#L275) have no message id; the original plugin discarded them. Current intake resolves unread history without reading it. A discovery worker per session stays responsive while a separate task awaits the ordinary Hermes turn's full cleanup. It admits authorized `/approve`, `/deny`, interrupt commands (`/stop`, `/new`, `/reset`) and pending clarify answers independently. Other ordinary messages remain oldest first outside Hermes, without burst merging. Exact-session replies and per-input read receipts remain explicit. The ordinary transport regression and the additional blocked-turn regression both failed against their respective earlier baselines before passing.
3. **Startup queue is not completed processing — handled in the fallback.** Hermes [run_inbound.py:199](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/run_inbound.py#L199) queues input during restore and returns `None`; its [startup queue](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/run_startup.py#L117) is process memory. The real test exposed that as an early receipt with no reply. The fallback waits for that gate to open. It currently depends on private Hermes readiness/task fields as well as the public processing-completion hook; a public awaited processing receipt would be a better upstream adapter contract.

4. **External identity-home mode — documented, not changed.** aw 1.36.40 rejects `events stream` when `AWEB_IDENTITY_HOME` selects an external home. The plugin inherits environment and supplies only `cwd` to its subprocess ([adapter.py](../packages/hermes-aweb-platform/adapter.py)). The refusal was reproduced in the investigation; the old gateway incorrectly reported “connected” while the stream exited repeatedly. The build now exposes that unproven/failed stream as retrying. A normal user starting Hermes from a shell without that variable follows the native-workspace path and avoids the refusal. An OATS/attached-identity environment can hit it despite following the old workdir recipe. The prepared flow explicitly unsets it. Proper external-home support belongs in aw; clearing it silently inside the plugin would conceal an authority-selection choice.

5. **History ceiling — unresolved.** [history endpoint](../server/src/aweb/routes/chat.py#L1850) caps the response at 2000 and [its query](../server/src/aweb/messaging/chat.py#L631) returns the newest window, without pagination. The fallback refuses a full 2000-row window because older unread input may be missing; below that boundary it drains all unread in order. It does not claim an unbounded oldest-first guarantee. The durable fix is an oldest-first unread cursor, not repeated newest-window reads.

6. **Crash exactly-once — unresolved.** Reply send and read are separate commands in [adapter.py](../packages/hermes-aweb-platform/adapter.py). A gateway crash after a visible send but before its read receipt can replay the input and duplicate the reply. A `message_id` event alone cannot remove that gap. A future durable response/processing receipt would need to bind the responding principal, triggering input, response operation and its committed result, preserving identity, recipient, session and changed-envelope conflict rules. It must not deduplicate globally on input id: different principals or response operations can legitimately answer the same input. Its bound would be preventing duplicate committed replies when recovering the same response operation; it would not make model or tool side effects exactly-once. No gateway-crash experiment or such protocol change was made here.

7. **P1 control/clarification regression — corrected, transport-tested.** The earlier fallback awaited each full turn before discovering another input. That prevented [Hermes’s active-session bypass](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/gateway/platforms/base.py#L4055) from receiving the input that would release its [clarify waiter](https://github.com/NousResearch/hermes-agent/blob/38d55b90dab7b37d7f26f0450b61851463fb1329/tools/clarify_gateway.py#L49). Independent discovery and control admission now preserve that bypass while ordinary turns stay serial. Immutable input routes are captured in task-local context and explicit reply anchors, so an inline control cannot overwrite the original turn’s destination/read id. Successful interrupt controls retire the cancelled original only after the control reply commits; unrelated shutdown cancellation stays unread. A real-stack stop/shutdown regression caught and corrected stale cancellation receipts. See the [upgrade checks](../packages/hermes-aweb-platform/README.md#compatibility-checks) for the remaining pinned private boundaries.

8. **P2 empty-history/fresh-hint race — corrected with deterministic evidence.** The old lane could retire after an empty query snapshot while a fresh hint had already observed it as running. The worker now clears its wake before fetching and retains hints across all awaits. It stays alive during idle periods; eventual idle removal is synchronous with its ownership check. The regression delays a completed real empty history response, observes the fresh real summary through the stream, and only then releases the response. It fails against `25d77a52` and passes against the current implementation. This evidence replaces the earlier unisolated retained-hint claim; the original reverted patch remains reverted in history.

9. **Mail retry, reply routing and stream health — corrected and transport-tested.** Read-confirmed dedup ids are recorded after successful delivery/acceptance and read acknowledgement, never before fetch. Failed fetches remain queued with bounded retries outside the event reader. A successful response whose read mark fails is remembered in this process so only its receipt retries. Mail replies use their input’s immutable route or explicit reply anchor instead of the latest conversation route; overlapping held-turn/control replies were tested using actual `aw mail reply` invocations. Health uses Hermes’s public `send_path_degraded` surface and runtime status: installed but unproven is retrying, an actual parsed stream frame establishes connected, and stream exit/error restores retrying until real recovery. aw’s internal reconnect diagnostic also degrades health without requiring process exit. No arbitrary gateway-crash exactly-once guarantee is added.

**Durable event-contract recommendation:** yes, server-side per-message actionable chat identifiers would be preferable to this adapter fallback, provided they enumerate all unread messages and preserve replay/order. Add oldest-first unread pagination and explicit response-operation receipt semantics through an opt-in or versioned contract. Preserve session-summary events for released consumers, existing history defaults and response shapes, and existing mark-read shapes; do not silently replace summaries, change unflagged history ordering, or require new receipt fields. Even adding one latest `message_id` to an old summary changes existing behavior: [aw deduplicates by event type and message id](../cli/go/cmd/aw/events.go#L224), and [channel-core passes a present message id into exact history fetch](../channel-core/src/channel.ts#L790). Mixed old/new consumer checks are required before release. This follows the [current wake/reconnect contract](receiving-events.md#current-reconnect-contract-no-resumable-cursor) and accepted decision `aweb/aweb-protocol-expert/decisions/released-clients-are-a-permanent-constraint.md@786b67f79977`.

The proposed response/processing receipt is distinct from [existing read state, which records presentation](receiving-events.md#presentation-and-acknowledgement), and from [existing receiver-wide message ingress replay protection](identity-messaging-contract.md#receiver-wide-replay-and-contact-compatibility). Read state does not transact model/tool execution. Ingress receipts protect acceptance of an already identified signed/protected message and retain their identity, recipient/session and changed-envelope conflict rules; they do not identify a later response operation or its processing outcome. The future facility must preserve those rules while binding the responding principal and response operation/result as described above. Wire design remains a separate protocol task; route it to the protocol expert. No server contract was changed here.

## Packaging and prepared install flow

Keep the plugin in the existing aweb repository initially. Hermes now supports monorepo subdirectories, so a separate repository is not required for a clean CLI install. A split repository would add release/ownership work without removing the compatibility issues. A pip entry point is supported but would need Python packaging that this directory does not currently ship. A bundled-plugin PR should follow real-model/Telegram validation and maintainer interest; no upstream PR was prepared for publication.

The install flow will pin the code commit included in the independent review; see the [plugin README](../packages/hermes-aweb-platform/README.md) for that exact pin. Until its ACK and required model validation, this remains a candidate build:

```bash
AWEB_PLUGIN_REF=df0b38022f1a27d22542776f4b93e8456c9e1ba9
export AWEB_PLATFORM_ENABLED=true
hermes plugins install awebai/aweb/packages/hermes-aweb-platform \
  --ref "$AWEB_PLUGIN_REF" --enable
```

The installed manifest name is `aweb-platform`; the platform registry/config name is `aweb`. A local symlink at `plugins/platforms/aweb` instead uses the discovery key `platforms/aweb`.

For the approved build, choose an already connected native aweb workspace belonging to this Hermes agent. The prepared native-workspace startup flow is:

```bash
unset AWEB_IDENTITY_HOME
cd /path/to/hermes-aweb-workspace
aw workspace status
export AWEB_PLATFORM_ENABLED=true
export AWEB_PLATFORM_WORKDIR="$PWD"
export AWEB_ALLOWED_USERS=example.aweb.ai/alice
export AWEB_ALLOW_ALL_USERS=false
hermes gateway run
```

Persist those settings in the selected Hermes home's `.env` for subsequent runs, and configure a real model with `hermes model` when its credential is provided. Keep Telegram's existing bot token and allowlist in Hermes's own credential configuration. Do not put credentials in this plugin's files or in aweb mail.

A model asked on Telegram to send **mail** needs an explicit mail-capable tool such as `aw --identity-home /path/to/hermes-aweb-workspace mail send ...`; the plugin's generic new-target sender currently uses chat, not mail ([adapter.py](../packages/hermes-aweb-platform/adapter.py)). Returning an asynchronous answer to Telegram also needs the original Telegram destination and request correlation. Those are the remaining workflow questions for the token/model-enabled experiment, not evidence already established by loading two platforms.
