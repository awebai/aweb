# ADAZ customer-path lab

This fixture proves the published client's registry selection and ordinary
messaging against stock RC2 services, then composes the separately reviewed
Cloud discovery journey. It runs only on an independently admitted disposable
Linux placement. It does not allocate a host or authorize a customer update.

The standalone path is BYOT: fixture DNS and namespace/team controller keys
remain on the fixture's controller machine; members hold their own signing
keys. The stock host verifies registered certificates and projects membership.
Controller authority is not inferred from a credential or a hostname. See
[BYOT authority](../../docs/byot-onboarding-contract.md#byot) and
[standalone onboarding](../../docs/byot-onboarding-contract.md#standalone-oss-path).
Only public certificates/facts cross into the stock registry/server. All local
identity, certificate, team and workspace state is created by the published CLI.

`adaz_lab_entry.py` is the fixed root watchdog entry. Its admission digest comes
in argv independently of the mounted admission file. The provider adapter must
first validate current ownership/address/lease and install the exact source,
Cloud bundle, published binary and read-only metadata. A source/context read
of that complete package precedes allocation. No environment/source fallback,
local Docker run, quota enlargement, bucket reset or service token is allowed
in the public client path.

The kernel cgroup contains host-side producers across session changes. The
supervisor stays outside it, journals its start before mutation, checks actual
APIs and limits, and stops/reaps it before reconciling Docker. Daemon resources
are separately inventoried, ownership/creation checked and removed by exact
identity. The fresh-host inventory also binds the separately named Buildx and
cache resources; Buildx is stopped first. Failed observations remain unknown
unless a subsequent successful complete inventory proves that exact resource
already gone; both raw calls are retained. An unanswered mutation stays
uncertain. Public-port absence, process absence, resource absence and provider
teardown have separate outcomes. The exclusive ingress fence remains until
provider destruction, protecting every inherited Compose publication.

The default-origin epoch uses the built-in `api.awid.ai` URL, normal DNS and an
OS trust store containing only a disposable added fixture CA. The client starts
as root only to install that public CA, then drops permanently to uid1000.
Stock services have real Redis quotas and DNS verification. The customer flow
creates identities/team/membership, connects both workspaces and exchanges
ordinary plaintext mail. Afterward the fixed quota probe observes an actual
429 and allowed DID-head neighbor. Finally a separate fresh reader must refuse
a discovered private origin. This negative never substitutes for success.

Cloud starts only after the standalone epoch finishes cleanly, with fresh
DB/Redis and the exact full-history source bundle. It runs the complete original
Cloud stage, including A.6d and optional phases, with no focused selectors or
cached stage result. Cloud's disclosed server development fixture remains
separate from the published client's stripped environment. A.6d's reviewed
body and19 assertions stay exact. The published installed CLI is bound by
wrapper/platform version, source commit and binary hash. The180s quota probe
and10s capture handshake follow the original journey. The root observer keeps
raw ownership-bound stock access logs and read-only Redis key/count/TTL data,
then publishes an atomic exclusive capture ack; capture is not enforcement.
A separate check requires the actual common access-log source and matching
namespace_get/did_head Redis windows. An expired/missing key fails that evidence
check; it is not reconstructed or populated from expected source behavior.

The fixed whole body is12600s, including preparation/default/Cloud/probe and
handshake; independent cleanup is600s. The proposed SDK backstop is13260s with
TERM/+30s KILL and its own evidence/provider completion reserve. No retry or
lease extension follows from a failure. SIGKILL/host/daemon death can prevent a
final receipt; independent operator recovery and exact provider teardown retain
that uncertainty. Private logs may contain disposable fixture keys and must not
be copied into shared handbacks.

The source/input controls are small Python unittest modules alongside this
file. Mocked launch/observation controls test decisions only. Linux cgroup,
Docker, TLS, Redis, published-client and Cloud runtime qualification must be
reported from the separately authorized native run, never inferred from those
controls. This package's first combined source review is still pending; no
native result is represented here.
