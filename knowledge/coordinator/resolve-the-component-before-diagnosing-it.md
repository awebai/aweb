A global framework version does not identify the capability code a running
instance uses. Match the recorded pin, resolved executable and actual refusal
predicate. A migration error does not prove the installed capability lacks a
feature; a migrated copy elsewhere does not change a retained source directory.

When integrity values differ, compare the complete installed file set and
metadata before concluding that executable content drifted. One September 2026
comparison found identical code but different pinned/unpinned source labels in
installation metadata. Preserve the installation's own reviewed integrity;
neither waive the mismatch nor assume code changes from labels alone.

Read the scope and target reported by diagnostics, not only their exit status.
Command-specific argument rules can differ. Package removal may also leave
separate adopted-configuration provenance, so a green package report is not proof
that every consumer of the old configuration disappeared.

Apply the same discipline to inherited procedures: follow their actual commands,
arguments and repository boundaries against current source. Linking to a current
authority document does not make a retired procedure current. Preserve the durable
reasoning and discard superseded command recipes during harvest.
