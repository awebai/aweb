# Decisions

* [OSS and Cloud are separate teams with separate expertise](oss-and-cloud-are-separate-teams.md) - No hosted-aweb expertise in the OSS souls or their knowledge; Cloud contributes to OSS through assignments or cross-team pull requests.
* [Durable expertise souls, task-purpose instances](expertise-souls-and-assignment-instances.md) - The roster is expertise, not job titles; coordination, implementation and review are assignments of an expert soul's instances.
* [Evidence and reproduction standard](evidence-and-reproduction-standard.md) - Every claim names its evidence or is labelled a hypothesis; a fix starts from a committed, reviewed reproduction of the reported failure on released code; an ACK separates what the reviewer verified from what it took on trust; wrong attempts are cleaned up completely.
* [Review blocks only on realistic failures](review-blocks-only-on-realistic-failures.md) - In the naapp and integrations lanes a review blocks a landing only on a realistic, supported-behaviour failure; a behavioural RED on released code is sufficient proof, speculative hardening is a non-blocking note, and full feature scope still stands.
* [One principal and one policy per request](one-principal-and-policy-per-request.md) - Every request carries one immutable original principal through every transport and credential bridge, evaluated by one per-operation policy that defaults to deny, with an explicit intra-team role model, no credential substitution and audit emitted at the decision point; tenant repositories and row-level security wait for evidence.
* [Keep the roster row, clear only the bad key](keep-the-roster-row-clear-the-bad-key.md) - When a roster row's encryption-key assertion fails verification, aw keeps the row exactly as the server projected it, clears only the key and warns once; it never fails the whole listing or drops the row, and encrypted sends to that row refuse with no plaintext fallback.
* [A signed conversation id is immutable](signed-conversation-id-is-immutable.md) - The server never stores or moves a message under any conversation id other than the one in the sender's signed payload; a fix that would merge into an existing thread must let the client find that thread before it signs, or refuse in a structured way.
* [A hinted 503 goes back to the caller, which waits it only within each step's own bound](a-hinted-503-goes-back-to-the-caller.md) - The server sends a delta-seconds Retry-After only for typed registry throttling; aw's transport returns a hinted 503 at once instead of blind-retrying it; a protected command step waits a hint only if it fits that step's own bound and the caller's deadline, and the installation lookup and the prepare each get a fresh bound.
* [An OATS deployment root is created without an address, and its creation is resumable](an-oats-root-has-no-address.md) - An OATS deployment root is created with aw id create --no-address, so its own key signs its did:aw mapping and no namespace controller key sits on deployment hosts; creation writes the key before registering, so a rerun resumes a partial run instead of minting a second root.
