## Traps that cost real time today

1. **An idle agent does not poll.** Mail *does* wake them (measured), but if one
   is parked at a prompt with unread work, nothing moves. `aw workspace status`
   says "active" regardless — it only reflects last-seen, which any `aw` command
   touches. **Capture the pane.** `esc to interrupt` present = working.
2. **A completed handoff is not progress.** The queue stalls just as easily on an
   idle *reviewer*. Watch branches, not just developers.
3. **`tmux send-keys` with long text lands in paste mode** — needs a *second*
   `Enter`. Verify it submitted.
4. **`aw task` 404s intermittently** (`aagh`). Retry; it succeeds immediately.
5. **`aw mail show --message-id` cannot resolve your OWN sent mail** — returns
   `No messages.` with exit 0. Use `--conversation-id`. `aw mail inbox` is
   unread-only by default.
6. **`cp` is interactive here.** It prompted, defaulted to *not overwritten*, and
   exited 0, leaving a modified file in the shared checkout. Use
   `git checkout --` to restore tracked files.

## The method the team built — this is the real asset

Nine measurement failures were found today against a handful of code defects.
Every one would have produced a confident wrong answer, and none was caught by
inspection — only by testing the instrument against a known case.

- **A red is evidence only if its failure text names the property.** Environmental
  failures present as timeouts and killed processes.
- **A zero is evidence only if the detector was shown positive** on the *actual*
  pattern, in a *separate invocation* (a control in the same invocation
  contaminates a process search).
- **A validated detector is not a valid experiment.** A passing control proves the
  instrument can see; only *removing the fix* proves the harness can go red.
- **Which control you need depends on which way the claim points.** Absence claim
  → known-positive (catches blindness). Presence claim → known-negative (catches
  looseness). The opposite control protects nothing.
- **A partial red is evidence, not a failure to reproduce.** Widening the mutation
  until everything reds destroys the information.
- **Classify every non-red, predicting the sensitivity set first.**
  Expected-sensitive-but-passed is a vacuous guard — the fix-removal run doubles
  as a free audit for the exact defect class this epic existed to find.
- **The harnesses most likely to be missing all this are the ones that are not
  tests** — log greps, process counts, exit-code checks, read-backs. Mutation
  habits don't reach them.

**Review standard now in force:** any verdict citing a harness must state either
*"the fix was removed and it redded, at these assertions"* or *"I did not check
whether this harness can fail."* Silence is not an option.

## Merge gate (five checks, all earned the hard way)

1. `git ls-remote` the **remote ref** — worktrees share one object store, so a
   peer can resolve and even test an unpushed commit.
2. Tip **equals** the ACK'd SHA. An ACK at a SHA is never an ACK of the branch.
3. Read the **whole range**, including the production diff.
4. Never stash another team's dirty tree — use `git worktree add --detach`.
5. Merge the **ACK'd SHA**, not the tip, when later commits are unreviewed.
