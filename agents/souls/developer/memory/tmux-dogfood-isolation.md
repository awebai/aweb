# Tmux dogfood isolation

When dogfooding or testing `aw team up` / tmux launcher behavior, never use the default tmux server for destructive or recreate flows. **Never run `tmux kill-server`**: it kills every live session on the targeted socket, and an empty/unset isolation variable can silently target the default server. For `aw` CLI dogfood that invokes plain `tmux`, set `TMUX_TMPDIR` to a fresh `mktemp -d` so aw's own tmux calls land on an isolated socket; for direct tmux commands, use a dedicated socket (`tmux -L awdogfood ...`) or the same isolated environment. Kill only the specific throwaway session, never the server; use throwaway session names/repos and assert nothing leaked to the default server.
